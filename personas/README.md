# 人设包（personas/）

一个角色 = 一个目录。机器人同一时间只用**一个**人设包，切换靠 `config.yml` 的
`persona.id`（不写 = `saki`）。

```
personas/
├── saki/                  ← 现成的例子（客服 Saki）
│   ├── identity.json      ★ 结构化：她是谁、怎么叫她、口癖、引用哪些作品
│   ├── persona.md         ★ 核心人设 —— **永远进提示词**
│   ├── persona-money.md     按需分册（聊到钱才带）
│   ├── persona-media.md     按需分册（聊到表情/动态才带）
│   ├── voices.md            示例对话（"人味"的关键，见下）
│   ├── cast.md            ★ 出场人物表（事件/剧情里点名的人，只给她认识的）
│   ├── life-events.md     ★ 日常事件库（她的一天 + 每个时段会发生什么）
│   ├── quest-ideas.md     ★ 剧情点子（二级主线剧情用）
│   ├── avatar.png           这个角色的 QQ 头像（可选，界面上传）
│   ├── ref.png              生图参考图 / 立绘（可选，界面上传）—— 见下面那节
│   └── prompt/              长段提示词：一段太长就用一个 md（例：qzone-guide.md）
├── miku/                  ← 你自己加的
└── _template/             ← 新建时照这个填
```

## 什么跟人设走、什么不跟

**判据一句话**：*换个角色，这份东西还成立吗？* 不成立 = 人设；成立 = 共用。

| 跟人设走（放 `personas/<id>/`） | 共用（放 `knowledge/`） |
| --- | --- |
| `persona.md`、`persona-money.md`、`persona-media.md` | `hzymtr-server.md`（服务器客服知识） |
| `identity.json` | `owner.md`（主人是谁） |
| `voices.md`（示例对话） | `relationship.md`（你和主人之间发生过什么） |
| `voices.md`（示例对话） | `group-memory.md`、`groups/`（群和群友） |
| `cast.md`、`life-events.md`、`quest-ideas.md`（**角色专属的数据文件**：人物关系 / 日常事件库 / 剧情点子） | |
| | `anime/`（动画库；**读哪几个由人设声明**，见下） |

⚠️⚠️ 上面那三份**每个包都要各有一份**，缺哪个，对应的生成器就是**哑的**：

| 缺这份 | 症状 |
| --- | --- |
| `life-events.md` | 每天的日常事件一条都不发（`0/3` 不动）；点「立刻发一条」只回「**现在这个时刻没有对应时段（0-7 点不发）**」，**看着像时段配错、其实是事件库空的** ✗（2026-10-14 爱音就是这个） |
| `cast.md` | 事件/剧情里点到的人，模型不认识 → 关系写歪、或者凭空多出不该认识的人 |
| `quest-ideas.md` | 二级主线剧情没有点子可抽 |

⇒ 新建人设包**照 `_template/` 把这几份一起复制过去**，别只复制 `persona.md`。
| | `learned.md`（群友教的知识） |
| | `anime.md` + `anime/`（二次元常识 / 作品库） |

⚠️ 一句话：**"她是谁"跟人设走；"这个世界是什么样"共用。**

## identity.json 的字段在管什么

代码里好几处要靠它（不然换个名字她还会说"我是小祥"）：

| 字段 | 谁在用 |
| --- | --- |
| `name` / `selfName` / `displayName` | 提示词里的自我介绍、自称 |
| `selfNames` | 判断"这句话是不是在说她"（登记忽略名单时别把自己写进去） |
| `callNames` | 群友点名叫她 → 必须回 |
| `nicknames` | 别人叫她外号也要正常回应 |
| `ambiguity` | 中文歧义词（例：「祥子」单独出现是叫她，但「骆驼祥子」是老舍的书） |
| `renameObjection` | 她不喜欢被叫某个称呼时的反应（拦「我不叫祥子」这种**答非所问的纠正**） |
| `matchNames` | **判据**要认的名字原子 —— 允许单字和变体（「祥」能匹配「小祥」「祥子」）。给 `mama.js`（「祥妈」算不算在叫她）、`search.js`（搜之前剥掉呼语）用 |
| `anime.works` | **读哪几个动画库** → `knowledge/anime/<名字>.md`。⚠️ **没声明就一份都不读**（不是"读全部"），换角色才不会串味 |
| `anime.keywords` | 问到这些词要联网搜（作品名、同作品的角色名）；也给「这算不算关于她自己企划的问题」用 |
| `address.owner` / `ownerFormal` | 她怎么称呼主人（平时 / 正式场合） |
| `address.ownerRule` | 什么时候用正式称呼（整句规矩，不在代码里拼） |
| `address.admin` / `member` | 留空 = 用群名片（大多数角色都该是空的） |
| `style.verbalTics` | 口癖 |
| `qq.nickname` / `qq.avatar` | 这个角色的 **QQ 昵称 / 头像**（头像 = 包里的文件名）。切换人设时**自动应用到真号** |
| `image.refs` | **生图参考图**（立绘）的文件名数组。群里让她"拍个照"时按它画 —— 见下面那节 |
| `prompt.*` | 提示词里的**整句**（整句替换，见下面）；**长段**放 `prompt/<名字>.md` |

⚠️ **没有 `library` 这个字段了** —— 表情包是**共用的基础包**，不跟人设走
（2026-09-21 用户定：「表情包也不用拆，直接当成基础包」）。

⚠️ **称呼分两个方向，别混**：

- **她怎么称呼别人** → `address` 段。
- **别人怎么称呼她** → 顶层那些字段（`name` / `selfName` / `callNames` / `nicknames` / `ambiguity`）。

⚠️⚠️ 还有一条**不是人设**的东西别放错地方：**"主人是谁"**（QQ 号、真实昵称）是
**共用事实**，在 `config.yml` 的 `ownerQQ` 和 `knowledge/owner.md` 里。
换人设改的是"**你叫他什么**"（`address.owner`），**不是**"你主人变成了别人"。

## 生图参考图（`ref.png` / `identity.image.refs`）

群里让她「拍个照」时，机器人会拿这张图当**人物参考**去调生图 API（见 `src/imagegen.js`，
服务商在 `config.yml` 的 `imagegen` 段里切）。

| | `avatar.png`（`qq.avatar`） | `ref.png`（`image.refs`） |
| --- | --- | --- |
| 干什么用 | 换**真号头像**（交给协议端） | 喂给**生图 API** 当人物参考 |
| 长什么样 | 正方形小图 | 立绘 / 半身，脸清楚 |
| 谁在管 | 管理界面「人设」页 → 上传头像 | 管理界面「人设」页 → 上传立绘 |

⚠️⚠️ **两个是分开的文件，别拿头像凑数** —— 头像一般太小太糊，生成出来的脸会飘。
⚠️ **不填 `ref.png` 时程序会退回用 `avatar.png`**（这样"刚配好就能用"），
但效果明显更差；界面上点「测试出图」会直接告诉你这次用了哪张参考图。
⚠️ `refs` 是**数组**（火山方舟支持最多 14 张参考图），界面只写第一张；
要放多张就手改 `identity.json`。
⚠️ 这个字段**故意没有**写进 `_template/identity.json` —— 它是"传文件"产生的，
不是让人填的，写进模板只会让"自动起草人设"多问一个填不出来的字段。

## 关于 `voices.md`（"人味"的关键）

光写"她说话短、有点傲娇"没用 —— 模型会给你一个**平均的动漫角色**。
`voices.md` 是**示例对话**：贴几段"这种场合她大概会这么说"，越具体越像。

建议至少覆盖：打招呼 / 被夸 / 被骂 / 被问到不知道的事 / 主动接话 / 拒绝。

## anime 库怎么用（**自动搜集时的规矩**）

`anime.md` 是**共用**的（所有角色都能用），但它可以按作品拆成 `knowledge/anime/<作品>.md`。
人设通过 `identity.json` 的 `anime.works` 声明引用哪几个 —— **不引用就看不到**。

⚠️⚠️ 用户定的规矩（2026-09-21），自动搜集角色资料时**必须**遵守：

| 情况 | 怎么做 |
| --- | --- |
| **复用一个已有的 anime 库** | **只读，绝不往里写**。搜集到的东西可以在给人看的时候显示，但不能落进那个文件 —— 否则给新角色搜集资料会**把老作品库写乱** |
| **新建 anime 库** | 才把搜集到的资料写进去 |

为什么这条重要：同一个作品的角色共享世界观（这些**可以**合并）；不同作品之间本来就该
"不知道对方的事"，而且合并会让字数爆炸（`anime.md` 已经 11KB 了）。

## ⚠️⚠️ 新角色上线前必做的一次验收（2026-10-13 用户定）

**角色名字就是"她自己"，不许被当成第三个人。**

现场：本机 agent 任务那句开工话，她说的是「这就动手**给祥子**写简历」——
可她自己就是丰川祥子 ✗。真因：那一步的提示词里只有一句抽象的「你就是客服小祥」，
没告诉她任务原文里的"丰川祥子"指的就是她自己。

**检查项**（建完人设照这个过一遍，详细版写在项目根 `AGENTS.md` 开头那节）：

1. 全部叫法从 `identity.json` 取（`name` / `selfName` / `shortName` / `callNames`），
   **代码里绝不许写死某个角色的名字**；
2. 凡是"以人设身份开口/落笔"的地方（系统提示词、她的模型改写、产物里的第一人称），
   提示词里都要写明「你就是〈本名〉，他说的这些名字全是你自己」；
3. **验收动作**：让她做一件**跟她自己有关**的活（例如「做一份〈本名〉的简历」），
   看她开口说的是「我」还是「她/祥子」—— 说成第三个人 = 不合格；
4. 顺手核对 `accounts/<QQ>.yml` 里按号分文件的值（`persona.ownerException` 之类），
   它们**不跟人设走**，换人设时要一起看。

## 加一个新角色

1. 复制 `_template/` 成 `personas/<id>/`；
2. 填 `identity.json`（`id` 用小写字母数字）；
3. 写 `persona.md`；
4. 写 `cast.md`（她认识谁 —— **只写她视角里认识的人**）和
   `life-events.md`（她的一天 —— 骨架在 `_template/life-events.md`，照它填满每个时段）；
5. `config.yml` 里写 `persona: { id: <id> }`，重启或让管理界面热重载；
6. 在管理界面「人设」页里可以直接切换、预览。

⚠️ 第 4 步最容易漏（2026-10-14 爱音就漏了 `life-events.md`，她的日常事件一直是哑的）。
建完在管理界面**点一次「立刻发一条」**确认能抽到事件 —— 抽不出来就是这份没写好。

⚠️ 三个坑：

- **别把真人做人设**（隐私 + 平台规则），输入像真人名字时程序会拦；
- **`persona.md` 会整篇进提示词** —— 写得越长，每次请求越贵。现成那个 88KB，
  是一次真实的教训：够用就行。
- ⚠️⚠️ **`identity.json` 的字符串值里，强调要用「」不要用 `"`**（2026-09-30 踩了三次）。
  JSON 的 `"` 是**定界符**，值里再出现一个裸的 ASCII 双引号，字符串就提前结束了 ——
  报错是 `Expected ',' or '}' after property value`，**位置指向那一行**，
  但真正的原因常常在**另一个字段**上（我就是在 `address.ownerRule` 和
  `prompt.ownerException*` 里各埋了一处，改一处才报下一处）。
  ✅ 中文引号「」、`''`、`**加粗**` 都不会破坏 JSON。
